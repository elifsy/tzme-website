页面继续使用同一份后台资料与 SEO 初始 HTML。此次调整不修改数据库内容、管理员权限或原始照片。

口径：同一台机器、本地构建预览、1440 × 1000 视口、禁用浏览器缓存，在页面首次显示后再等待 1.8 秒，记录已传输资源，包含浏览器预加载的临近区域。MB 按十进制计算；这些数值不代表所有网络环境的实际加载秒数。测试未写入访问统计或业务资料。

## 图片

`scripts/build-image-variants.mjs` 为项目已有的展示照片、背景和设备图生成不同宽度的 WebP。原始文件保留；查看产品大图、企业照片原件和新闻附件仍可使用原始资料。正文图的尺寸适配仅发生在展示组件，编辑器保存的 HTML 不被改写。

浏览器通过 `srcset` / `sizes` 选择尺寸，未知的上传图片继续使用其原路径。产品图继续沿用原始主体边界数据，使透明底设备的布局和阴影保持一致。

图片文件位于 `public/assets/optimized/`，文件名带源内容指纹。前端清单为 `src/data/imageVariants.json`，Java 首屏渲染清单为 `server/src/main/resources/image-variants.json`。`npm run dev` 与 `npm run build` 会先运行资源准备；未变化的源图不重复编码。

## 脚本、数据与 3D

官网不再提前加载后台会话弹窗和登录表单；后台各管理模块在进入对应页面时加载。官网入口脚本从约 475 KB 降至 415 KB，后台入口从约 532 KB 降至 331 KB（构建后的未压缩体积）。

产品中心先显示页面及场景图片，再在视口附近的空闲时间初始化 3D。直接访问产品列表锚点时，屏幕外的场景不立即占用 GPU。旋转、特写、缩放、复位及设备动作保持原有行为。

同一时刻的相同公开 GET 请求合并；后续读取依然重新获取数据，没有增加可能导致后台修改迟迟不生效的长期缓存。后台刷新与带独立取消信号的请求不合并。

服务端把当前公开页面的 SEO 元数据同时嵌入初始数据，首次进入时直接复用；站内切换仍重新获取目标页面信息。原有的加载失败与无 JavaScript 可读页面保留。

## 构建和验证

先执行 `npm run build`，再打包 Java 后端，并将同一次构建的 `dist/` 和 JAR 一起发布。图片清单随前端资源准备更新，无需新增数据库迁移。

基础回归：`node --test scripts/check-loading.mjs scripts/check-analytics-contract.mjs scripts/check-article-categories.mjs`。后端测试覆盖公开首屏、图片替换、原始资料保留、账户权限和数据校验。
